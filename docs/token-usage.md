# Token 用量测量与优化（AGENTS §9 2i）

本文记录每个用户操作发出的 AI 请求有多少输入 token，以及本轮优化前后的对比。测量完全离线：用假的服务商记录请求体，**不联网、不需要 API Key**。

## 怎么测

```bash
npm run token-usage            # 打印下表，并写到 .cache/token-usage.md
node scripts/token-usage.mjs out.md
```

- 测量代码在 `tests/tokenUsage/`，由 `tests/tokenUsage.test.ts` 运行（平时作为普通测试执行：检查结果确定、每个操作都测到）。
  - `scenarios.ts`：用提示词注册表的真实构建函数与服务里的同一套拼装方式生成请求（讲解、作业、划词、课时、导师、判分等）。
  - `quizScenario.ts`：直接跑真实的 `QuizService`（fake-indexeddb + 记录请求的假 AI），分批、补题、重试都按实际发出的请求记录。
  - `fixtures.ts`：固定的教材段落（≤800 字的分块）、一份线性代数作业（第 2 题有 4 个小题）、中文 + LaTeX 的讲解正文、问答历史。
- **token 估算**（`estimate.ts`）：没有内置分词器，按字符类别估算：汉字约 0.75 token/字，英文约 4 字母/token，数字约 2.5 个/token，ASCII 标点与 LaTeX 符号约 0.6 token/个，换行约 0.3。与常见 BPE 分词器相差约 ±20 %，用于比较请求形状的前后变化，不是账单。
- **前缀缓存**：DeepSeek、OpenAI 等服务商会自动缓存与之前请求相同的前缀（按 64 token 为单位），命中部分价格约为 1/10 甚至更低。表中「可命中前缀缓存」= 每个请求与**同一操作内**更早请求的最长相同前缀（向下取整到 64 token）；「折算输入」= 未命中 + 命中 / 10。只在一个操作内计算（冷启动），跨操作的系统提示复用没有计入，所以实际命中只会更多。
- 假设的输出上限为手动 8192（`max_tokens` 列只说明各请求申请了多少，按实际生成的 token 计费，不是按上限）。

结论：

- 输入 token 合计减少约 6 %，按前缀缓存折算后减少约 12 %；受影响的操作减少 20 %–34 %。没有改动的操作（课程分析、课时、划词等）的请求本来就是「稳定内容在前」，或者内容本身无法再省而不影响质量（见下文「没有做的」）。
- 课程分析是单次最大的请求（两部分约 2.4 万 token），远大于其它操作；作业讲解与测验是最常用的大头。
- 输出 token（尤其是推理模型的思考 token）通常比输入更贵，但取决于模型本身，离线无法测量；本轮没有压低任何 `max_tokens`，避免截断回归。

## 做了什么

1. **测验 `quiz-generator/v8`**（v7 保留，注册表切到 v8；测验不缓存，不会让任何已有内容失效）
   - 系统提示只描述本测验计划的题型的规则与 JSON 字段（选多选题时保留它引用的单选规则 4；A2 病例题规则只在有单选题时保留）。同一测验的每一批、补题与重试系统提示完全相同。不传题型时与 v7 逐字相同。生物「单选 + 简答」的系统提示从约 2 700 降到约 1 800 token。
   - 用户提示改为稳定内容在前：主题 / 描述 / 语言 / 教授出题风格 / 教授出题习惯 / 来源片段，然后才是本批的知识点、「避免重复」与出题计划。
   - `QuizService`：「避免重复」只列最近 30 题、每题压成一行并截到前 160 字（`avoidRepeatingList`）；补题轮次按第一轮的份数分片段，而不是把全部片段（最多 24 段）发给一两道题，且第 1 份与第一批完全相同，可命中缓存。
2. **交互导师 `tutor/v3-question`、`tutor/v2-evaluate`**（系统提示不变）：同一主题会话中每道题、每次判分都相同的来源片段移到前面，难度 / 避免重复 / 作答等放在最后。
3. **完整讲解 `homework-walkthrough/v7`**：分小题写（以及详细版分小题）时，「这一请求只写小题 (b)」这一行移到题目、出处、教授答案、旧解法这些共用块之后，兄弟小题共享整段前缀。只改位置不改文字；`CACHE_VERSION` 仍为 `v1`，各节哈希不变，**已就绪的讲解不会显示「可更新」**。
4. **作业提示 / 解法、复习讲解、检查答案、逐题问答**：题目没有出处分块时，`sourceText` 回退为题目原文，以前会把题目原文当作「来源段落」再发一遍。现在 `promptSourceText` 去掉这份重复（逐题问答的模板总会打印来源块，改为一句说明）。提示词模板未改；复习讲解与检查答案的缓存哈希不含提示词文字，不受影响。
5. **做练习题 `practice-generate/v2`、口试 `oral-exam/v2`**：教授出题习惯块从末尾移到逐批 / 逐题变化的内容之前（文字不变）。
6. **轻量模型（可选）**：设置页新增「轻量模型」（同一服务商、同一密钥与 Base URL，留空 = 使用主模型）。只用于简单任务：课程词汇释义、填空等价核对、简答题按得分点核对、题目翻译、考点 AI 匹配、提取得分点（`AIService.light()` / `withLightModel`）。输出上限按轻量模型自己的上限解析。讲解、课时、出题、课程分析始终用主模型。它不减少 token 数，但这些请求可以用便宜得多的模型。

## 没有做的（以及原因）

- **没有压低 `max_tokens`**：按实际生成计费，上限只防止失控；压低可能让推理模型截断（思考 token 也计入上限）。
- **课程分析的分块 id**：每个分块前缀带 36 位 UUID（约占输入的一成，且 AI 输出的 `sourceChunkIds` 也要逐字写出 UUID）。改成短别名需要改提示词与校验映射，而且 `document-analyzer` 升版会让所有课程的分析变成「提示词已更新」并重新分析——列为高风险，未做。
- **课程分析只重做变化的部分**：目前分部分结果只在内存里、成功后清空，资料一变就重读全部部分。持久化分部分结果需要新增存储，未做。
- **完整讲解开头 / 小结合并成共享前缀**：两次请求的用户内容相同但系统提示不同；要共享前缀需把各自的要求移到用户提示末尾，会改变两份提示的结构，未做。
- **有教授答案时不再发送「旧 AI 解法」**、分小题时只发本小题相关内容、划词历史缩短：都会改变模型看到的内容，可能影响讲解质量，未做。
- **可视化系统提示按科目裁剪数学规则**：会改变非数学科目课时配图的生成，未做。
