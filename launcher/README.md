# 启动器（Launcher）

## 为什么需要启动器

本项目是 **纯浏览器应用（Vite + React）**，但开发服务器本身需要 **Node.js** 才能运行。

浏览器网页没有权限检测或安装 Node.js，所以这部分工作必须由**启动器**在系统层面完成：

```text
启动器 = 系统环境管理（检测 Node.js / 安装依赖 / 启动服务器）
网页   = AI 学习平台（课程、导师、测验、错题本…）
```

两者职责分离。网页端不会、也不能尝试安装 Node.js。

## 文件

| 文件 | 平台 | 说明 |
| --- | --- | --- |
| `windows.ps1` | Windows | PowerShell 启动器，由项目根目录的 `Start.bat` 调用 |
| `unix.sh` | macOS / Linux | Bash 启动器 |
| `launcher.log` | — | 运行日志（已被 `.gitignore` 忽略，不会提交） |

## 使用方式

### Windows

双击项目根目录的 **`Start.bat`**。

### macOS / Linux

```bash
./launcher/unix.sh
```

如果提示没有执行权限：

```bash
chmod +x launcher/unix.sh
```

## 启动器会做什么

```text
1. 检测 Node.js 是否存在
2. 检测版本是否满足 package.json 的 engines.node（当前为 >=20）
3. 检测 npm 是否可用
4. 缺少或版本过低 → 提示 → 等待你确认 → 才尝试安装
5. 安装后重新检测（不假设成功）
6. 检查依赖是否完整、是否过期
7. 启动开发服务器并打开浏览器
```

环境已经满足时，**不会进行任何安装操作**，直接启动。

## 版本要求从哪里来

唯一来源是 `package.json`：

```json
"engines": {
  "node": ">=20"
}
```

启动器读取这个字段，不硬编码版本号。

## 安装方式

**只有在你明确确认后**才会执行安装。

| 平台 | 方式 |
| --- | --- |
| Windows | `winget install --id OpenJS.NodeJS.LTS --exact` |
| macOS | 检测到 Homebrew 时：`brew install node` |
| Linux | 按发行版选择 `apt-get` / `dnf` / `pacman` / `zypper` |

如果缺少上述工具，启动器**不会**擅自安装它们（例如不会为了装 Node.js 而先装 Homebrew），
而是给出官方下载地址，由你手动安装。

## 安全与隐私

启动器**只**检测：

```text
Node.js 是否存在及版本
npm 是否存在及版本
操作系统类型
```

**不会**收集或上传：

```text
用户名 / 硬件信息 / MAC 地址 / IP 地址
文件列表 / 浏览器历史 / 个人文件
```

没有遥测、没有分析、没有崩溃上报。

同时保证：

- **不静默安装** —— 任何安装都必须先得到你的确认
- **不绕过系统权限** —— 需要管理员权限时由系统弹出确认窗口，启动器不保存密码
- **不下载第三方安装包** —— 只使用系统包管理器或官方渠道
- **日志不含密钥** —— `launcher.log` 只记录检测结果与错误信息

## 常见问题

**装完 Node.js 后仍提示未检测到？**

关闭当前窗口，**重新打开**后再运行启动器 —— 环境变量需要新窗口才会生效。

**端口 5173 被占用？**

通常是上次的开发服务器没关。启动器会询问是否结束该进程。
本应用必须固定使用 5173：浏览器按来源（origin）隔离本地数据，换端口会看到空的工作区。

**依赖装不上？**

删除 `node_modules` 后重新运行启动器。启动器在检测到跨平台或损坏的
`node_modules` 时也会自动清理重装。

## 手动启动

不想用启动器也可以直接执行：

```bash
npm install
npm run dev
```

前提是本机已有符合要求的 Node.js。
